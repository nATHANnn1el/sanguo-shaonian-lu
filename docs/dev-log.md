## 决策记录
| # | 决策 | 原因 | 影响 |
|---|---|---|---|
| D1 | 做**原创**游戏，不复刻任何商业游戏的素材/数据 | 版权与可交付性；参考品类的「机制思路」不受保护，名称/文案/数值必须自建 | 所有技能名、数值、文案原创；占位美术 |
| D2 | 先做 Web/PWA 而非原生 App | 用户要在手机上玩；PWA 零安装成本、迭代快、同一份代码到处可玩 | 需 HTTPS 才能完整安装/离线 |
| D3 | DOM + SVG，不用 Phaser | 回合制卡牌 UI 不需要游戏循环；包体小，可测试 | 无粒子/骨骼动画；后续可局部引入 |
| D4 | 引擎输出事件日志，UI 回放 | 可测试、可复现、可跳过/倍速零成本 | 先算后演：结果开战即存盘 |
| D5 | 速度排序，每回合重排 | 与「速度」属性、速度增减益自然联动 | 需要在界面显示行动顺序条 |
| D6 | 怒气：起始 1、普攻 +2、受击 +1、满 4 放绝技、上限 8 | 约每 2 次行动能放一次绝技，节奏快、便于手机短局 | 数值在 `RULES`，可调 |
| D7 | 合击 = 羁绊上的可选字段，由发起者在怒气满时代替绝技释放 | 不需要新输入；数据可扩展；与「怒气资源」一致 | 搭档阵亡则退化为普通绝技 |
| D8 | 速度不随等级成长，只受羁绊影响 | 避免出手顺序被养成彻底改写，保持武将定位 | 敌我速度对比主要由武将自身决定 |
| D9 | 存档版本号 + 迁移表 + 防御式清洗 | 内容会增删武将；未来会改结构 | 坏档备份到 `.bak` 而不是静默覆盖 |
| D10 | 自建最小 Service Worker | 需求简单、少依赖 | 发新版需手动换缓存名 |
| D11 | 先开发核心再做 UI，核心有测试门禁 | 规则是游戏的根，UI 可换 | UI 目前只有冒烟 E2E |

## 问题记录
| # | 现象 | 根因 | 处理 |

| P1 | `git commit` 报 Author identity unknown | 盒子无全局 git 身份 | 设置**仓库级**身份，不动全局 |
| P2 | Ajv 报 “schema with key or id already exists” | 每个测试重复编译同一 Schema | 按文件名缓存已编译的校验器 |
| P3 | 合击测试打错目标 | 敌人普攻打前排，测试里发起者站前排被先打死 | 让发起者站后排（a3），搭档站前排，初始怒气 8，断言事件序列 `combo → ultimate` |

## 部署记录（GitHub Pages，2026-11-01 19:30 AEDT）
- D12：保持 Vite `base: './'`（相对路径），不写死 `/<repo>/`。理由：manifest 的 `start_url`/`scope`、`sw.js` 注册路径、图标和 SW 缓存清单全部用相对路径，换仓库名或自定义域名无需重新构建。已在 `/sanguo-shaonian-lu/` 子路径下跑 E2E 验证通过。
- D13：用 Actions 的官方 Pages 流程（`upload-pages-artifact` + `deploy-pages`），工作流里先跑 `npm test` 再构建，测试失败不发布。
- P13：当前环境的 GitHub 连接器没有「创建仓库」「提交文件」「启用 Pages」的工具，盒子上的 `gh` 也未登录，所以无法由代理直接推送。需要用户先在 GitHub 上建一个空的公开仓库（建议名 `sanguo-shaonian-lu`），再由具备推送能力的方式（登录 `gh` 或云端代理）推送本仓库，并在仓库 Settings → Pages 把 Source 设为 “GitHub Actions”。
