## 1. 引言

### 1.1 目的
定义《三国少年录》MVP 的功能与非功能需求，作为设计、实现与验收的依据。

### 1.2 产品定位
一款**原创**的三国题材回合制卡牌养成手游（网页/PWA）。玩法参考同类「站位 + 自动回合制 + 怒气绝技 + 羁绊合击」的通用品类机制，但**名称、技能、数值、文案、美术全部原创**，不使用任何现有商业游戏的素材或数据。

### 1.3 范围
MVP 只含：1 章 10 关、12 名历史武将（蜀 6 / 魏 6）、3+3 站位、自动战斗、怒气与绝技、4 个羁绊（其中 1 个含合击技）、升级与进阶、本地存档、PWA 安装。
**不含**：联网/账号、抽卡、PVP、排行榜、付费、音效、扫荡、多章节。

### 1.4 术语
| 术语 | 含义 |
|---|---|
| 阵位 | 6 个站位：0–2 为前排，3–5 为后排 |
| 怒气 | 每名角色的行动资源；满 4 点释放绝技 |
| 绝技 | 武将的大招，消耗 4 点怒气 |
| 羁绊 | 指定武将同时上阵时激活的属性加成 |
| 合击 | 羁绊附带的联合技；发起者怒气满且搭档存活时代替绝技释放 |
| 银两 / 将魂石 | 两种货币：升级用银两；进阶用将魂石 |

## 2. 总体描述

### 2.1 用户与运行环境
- 用户：在手机上玩单机养成游戏的玩家。
- 环境：手机浏览器（iOS Safari / Android Chrome），竖屏，触控；亦可桌面浏览器。
- 安装：支持「添加到主屏幕」（PWA）。需 HTTPS 或 localhost 才能完整启用 Service Worker 与离线。

### 2.2 假设与约束
- 纯前端，无后端；数据存于 `localStorage`。
- 技术栈：TypeScript（strict）+ Vite；UI 使用原生 DOM + 内联 SVG；测试使用 Vitest + Ajv（JSON Schema）+ Playwright（E2E 冒烟）。
- 美术为程序生成的 SVG 占位图（可后续替换为正式资源）。

## 4. 非功能需求
| ID | 需求 | 指标 | 状态 |
|---|---|---|---|
| NFR-01 | 移动端适配 | 竖屏，最小宽度 360 px，触控目标 ≥ 40 px，适配刘海安全区 | ✅ |
| NFR-02 | 性能 | 生产包 JS ≤ 100 KB（实测 gzip 17.7 KB）；单场战斗模拟 < 50 ms | ✅ |
| NFR-03 | 原创性 | 所有技能名、数值、文案、美术均为原创，不含第三方游戏资产 | ✅ |
| NFR-04 | 可测试性 | 战斗引擎为纯函数，与 UI 解耦 | ✅ |
| NFR-05 | 可维护性 | 数据与代码分离，数据有 Schema；TypeScript strict | ✅ |
| NFR-06 | 离线可用 | 首次加载后断网仍可游玩 | ✅（需 HTTPS/localhost） |
| NFR-07 | 隐私 | 不收集数据，不联网（除静态资源加载） | ✅ |

## 5. 已知缺口（超出 MVP）
无音频；美术为占位；单章；无扫荡；战斗开始即结算（中途退出仍计入结果）；Service Worker 在局域网 HTTP 地址下不可用（见 `architecture.md` §7）。
